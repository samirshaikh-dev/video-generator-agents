MEELTE MULTI-AGENT VIDEO PROMPT SYSTEM
PROJECT REQUIREMENTS
File: req.txt
Purpose: Define a reusable workflow that turns a Meelte campaign brief into a
structured, brand-safe, model-ready text-to-video prompt package.

===============================================================================
1. PROJECT OBJECTIVE AND SCOPE
===============================================================================

Build a reusable multi-agent system for planning short Meelte marketing videos
and authoring prompts for text-to-video models. The workflow turns a rough
request into a grounded creative plan, a time-aware video prompt, and a
reviewable delivery package.

The primary deliverable is a prompt package, not a rendered video. The
workflow must be useful without a video provider, provider account, or
provider-specific SDK. A host that has an authorized video-generation tool may
use the approved prompt, but the workflow must never claim a video was
generated unless a real provider call returned an asset.

The system must:
- Preserve Meelte's visual identity and factual accuracy across campaigns.
- Translate short or incomplete briefs into a clear video concept.
- Specify what happens over time, not just describe a still frame.
- Produce provider-neutral prompts that can be adapted to a selected model
  without silently changing the approved creative.
- Check prompt clarity, timing, continuity, brand compliance, and feasibility.
- Support targeted revisions while preserving prior prompt versions.
- Remain modular so video models, tools, and agent implementations can change.

Out of scope for this documentation change:
- Implementing a video provider, rendering service, editor, or asset store.
- Claiming prompt generation itself creates or validates a rendered video.
- Requiring a specific video model, API, framework, or agent library.

===============================================================================
2. MEELTE BRAND AND VIDEO STYLE
===============================================================================

Read `brand/meelte-brand.json` for the canonical palette, typography, logo,
copy, and brand rules. Do not copy brand values from memory or let a prompt
override them without an explicit user-approved brand exception.

Brand personality:
- Playful, approachable, modern, friendly, community-oriented, and
  technology-driven.
- Make local business owners feel understood and empowered.
- Communicate practical business value rather than a technical product
  brochure.

Default visual direction:
"Playful Modern Branding + Flat Vector Illustration + Bold Editorial
Advertising."

For video, preserve the approved 2D commercial vector language while adding
controlled, legible motion:
- Simple, motivated character and prop movement.
- Clean shapes, minimal outlines, subtle gradients, and soft shadows.
- Stable character, wardrobe, environment, and palette across shots.
- A clear subject and uncluttered frame; motion must not create visual noise.
- Camera moves should be purposeful and physically coherent.
- Prefer a small number of readable actions over rapid or competing motion.

Do not default to photorealism, 3D, generic stock footage, unrelated
illustration styles, or complex camera moves. Permit a different style only
when the user explicitly requests it and record that override in the brief.

Brand palette:
- Orange: #FEA711
- Purple: #743BAA
- Lavender: #F4EFFD
- Charcoal: #171923
- White: #FFFFFF

Orange and purple must remain the dominant brand pair. Use the other tokens
for their established supporting roles. Do not introduce a dominant third hue
without a campaign-specific reason recorded in the brief.

Typography and in-video text:
- Use bold geometric sans-serif direction: Poppins, Manrope, or Plus Jakarta
  Sans.
- Keep headlines short (maximum 6 words), supporting copy to 14 words, and
  CTA to 4 words, unless the brand file changes those limits.
- Prefer clean text-safe compositions and deterministic post-production
  overlays for exact copy. Do not rely on video models to render the logo,
  small text, prices, dates, or legal copy accurately.
- Use only exact user-supplied strings for campaign copy. Never invent claims,
  prices, discounts, deadlines, statistics, or capabilities.
- Use the supplied logo asset only. If unavailable, reserve a clean logo zone
  and mark it `logo pending`; never generate, trace, or approximate the logo.

===============================================================================
3. VIDEO BRIEF AND OUTPUT FORMATS
===============================================================================

Normalize each request into a VideoBrief that records:
- Objective, target audience, and the intended viewer takeaway.
- Platform and placement.
- Desired duration and aspect ratio / delivery dimensions.
- Main subject, setting, and the action or change that happens over time.
- Exact headline, dialogue, voiceover, CTA, and other supplied copy.
- Music, sound effects, ambience, and audio exclusions, if requested.
- Required and prohibited elements.
- Reference assets, logo asset, and continuity references.
- Style overrides, approval mode, and provider/model target if supplied.

Reasonable defaults when the request does not specify:
- Platform: Instagram Reels / short-form social.
- Aspect ratio: 9:16 vertical.
- Duration: 15 seconds, subject to the selected model's supported limits.
- Approval mode: automatic prompt review; do not infer consent to render.

Ask at most one clarification question, and only if a missing detail materially
changes the creative (for example, conflicting objectives, a required exact
claim, an essential asset, or a requested duration/format that cannot be
reconciled). Otherwise select a sensible default and state it in the brief.

Treat dimensions, frame rate, duration, audio support, and other model limits
as requested targets until a selected provider confirms them. Do not promise
provider-specific capabilities in a provider-neutral prompt.

===============================================================================
4. MULTI-AGENT ARCHITECTURE
===============================================================================

Use the project's existing agent framework and conventions. Keep specialist
responsibilities and handoff contracts separate.

A. ORCHESTRATOR / VIDEO CREATIVE PRODUCER
Responsibilities:
- Normalize the request, own the canonical brief, and manage the workflow.
- Decide which specialists are needed and sequence their work.
- Resolve conflicts using the user brief and canonical brand rules.
- Track approvals, prompt versions, revisions, errors, and delivery status.
- Never invent campaign facts, product capabilities, or user-approved copy.
- Distinguish a prompt package from a generated video asset.

B. BRAND GUARDIAN
Responsibilities:
- Read the brand source of truth and define applicable brand constraints.
- Check palette, style, typography, tone, and correct use of logo assets.
- Flag requested exceptions or conflicts without silently changing the brief.
Output: brand constraints, conflicts, and a video-specific compliance checklist.

C. CAMPAIGN STRATEGIST
Responsibilities:
- Identify the campaign objective, audience insight, and single key message.
- Recommend concise copy only when requested or needed.
- Keep claims grounded in information supplied by the user.
Output: campaign message, approved copy, and any claim risks.

D. VIDEO DIRECTOR / STORY AND MOTION PLANNER
Responsibilities:
- Turn the approved message into a visual concept with a clear beginning,
  progression, and ending or loop point.
- Define a time-coded sequence of shots or beats whose durations add up to the
  requested total duration.
- Specify subject action, camera/framing/movement, composition, transitions,
  lighting, and continuity across shots.
- Keep motion readable, purposeful, and consistent with the brand style.
Output: video concept, shot plan, motion direction, and continuity notes.

E. VIDEO PROMPT ENGINEER
Responsibilities:
- Convert the approved brief and shot plan into a clear, provider-neutral
  text-to-video prompt.
- Keep approved creative decisions intact while adapting structure to a named
  provider only when the user or host identifies one.
- Separate prompt content from optional provider settings and unsupported
  assumptions.
- Provide negative constraints when the target model supports them.
Output: prompt package, model-specific notes when justified, and prompt
version.

F. VIDEO PROMPT QA
Responsibilities:
- Check the prompt against the brief, brand constraints, timing, motion
  feasibility, shot continuity, exact copy, and provider-neutrality.
- Identify ambiguity, contradictions, excessive simultaneous actions, and
  unsupported technical promises.
- Give targeted revision instructions; do not rewrite approved campaign copy.
Output: pass/fail status, severity-tagged issues, and revision instructions.

G. VIDEO GENERATION ADAPTER (OPTIONAL, FUTURE INTEGRATION)
Responsibilities:
- If implemented and configured, call the selected provider through a
  provider-independent adapter.
- Validate the response and report the provider, model, parameters, asset,
  status, and explicit error.
- Never fabricate a successful generation result.
This adapter is not required for prompt-package delivery.

H. FINALIZER / PROMPT PACKAGE DELIVERY
Responsibilities:
- Save or return the approved prompt package and its metadata.
- If an actual generated video is supplied by a configured provider, preserve
  the raw asset and report verified delivery details separately.
- Never label a prompt as a rendered, reviewed, or brand-approved video.

===============================================================================
5. WORKFLOW AND HANDOFFS
===============================================================================

Default workflow:
1. Normalize the request into VideoBrief; state defaults.
2. Load brand rules and identify conflicts.
3. Develop the campaign message, unless approved copy was supplied.
4. Create the video concept, time-coded shot plan, and continuity rules.
5. Build the provider-neutral video prompt package.
6. Run the prompt QA gate and route issues to their owner.
7. Save or return the approved prompt package with its version and metadata.
8. If an explicitly configured provider is available and generation was
   requested, call it as a separate optional step; otherwise stop at the prompt.
9. Review a returned video only if an actual video asset is available.

Workflow rules:
- The brief is the source of campaign facts; the brand file is the source of
  brand constraints.
- Specialists may not silently change approved copy, message, or style.
- Time-coded shot durations must sum to the requested video duration.
- Preserve character, prop, wardrobe, setting, palette, and screen direction
  across shots unless a planned transition changes them.
- Do not add text, dialogue, voiceover, sound, or product features the user did
  not request or supply.
- Use bounded revisions; do not loop indefinitely.
- Keep every prompt version and revision. Never overwrite prior versions.
- A provider failure is explicit and must not be presented as a delivered
  video.

===============================================================================
6. REUSABLE SKILLS
===============================================================================

Reuse existing skills when relevant and adapt image-specific guidance to
temporal video composition rather than treating video as a still image.

Required reusable capabilities:
1. `meelte-brand-system` — palette, type, logo, tone, and brand compliance.
2. `marketing-creative-strategy` — audience insight, message, concise copy,
   and claims.
3. `flat-vector-illustration` — default visual treatment, adapted for motion
   and cross-shot continuity.
4. `advertising-layout-composition` — hierarchy, framing, safe zones, and
   responsive aspect ratios.
5. `video-prompt-engineering` — time-based prompt structure, shot/action
   descriptions, camera direction, continuity, negatives, and model adapters.
6. `video-quality-review` — prompt and, when available, rendered-video QA.
7. `campaign-series-consistency` — recurring visual language and controlled
   variation across multiple videos.

The video-specific skills may be added as part of a later implementation.
Do not claim a referenced skill exists until its files are present.

===============================================================================
8. USER EXPERIENCE REQUIREMENTS
===============================================================================

The user should be able to:
- Submit a natural-language request and receive a structured VideoBrief.
- Choose or confirm platform, duration, aspect ratio, and intended model when
  it materially affects the result.
- Supply exact copy, dialogue, audio direction, logo, and reference assets.
- Ask for campaign copy suggestions without accepting unsupported claims.
- Request targeted changes to a shot, action, camera move, style, or timing.
- Reuse a previous campaign's visual language while allowing controlled
  variation.
- See whether the request is being planned, prompt-authored, reviewed, or
  optionally rendered.
- Receive the prompt package and limitations even when no video provider is
  available.

===============================================================================
9. REFERENCE ASSETS AND BRAND MEMORY
===============================================================================

Maintain a source of truth for:
- Meelte logo and approved variants.
- Brand palette, typography references, and style-guide images.
- Approved campaign examples, motion references, and reusable characters.
- Platform format targets and any provider-specific constraints.

Requirements:
- Keep reference assets separate from generated outputs.
- Use references as style or continuity guidance, not as content to copy
  exactly.
- Mark approvals explicitly; a generated asset is not an approved reference
  merely because it exists.
- Do not send private or unapproved assets to a provider without consent.
- Allow brand rules to change centrally without editing every agent prompt.

===============================================================================
10. QUALITY AND ACCEPTANCE CRITERIA
===============================================================================

The prompt workflow is acceptable when:
- A natural-language Meelte request produces a structured VideoBrief.
- The handoffs produce a traceable message, video concept, shot plan, prompt,
  and QA result.
- The prompt describes temporal actions and camera direction, not only a
  static frame.
- Shot timings add up to the requested duration, and continuity is explicit.
- The prompt follows Meelte's style and brand constraints unless the user
  explicitly approved a recorded override.
- Exact user-supplied copy is preserved, and no unsupported claims are added.
- The prompt is provider-neutral unless a target model was specified.
- The workflow can return a complete prompt package without a provider.
- Optional provider failures are visible and never shaped as success.
- Prompt versions, decisions, reviews, and limitations are retained.
- A provider can be added later without rewriting creative planning agents.

Suggested prompt QA checklist:
[ ] Objective, audience, platform, duration, and aspect ratio are explicit.
[ ] The central action has a clear progression and ending or loop point.
[ ] Shot timings sum to the requested total duration.
[ ] Each shot has a clear subject action and purposeful camera direction.
[ ] Character, props, setting, style, and screen direction remain consistent.
[ ] Motion is readable and no shot contains contradictory directions.
[ ] Orange and purple remain the dominant brand pair.
[ ] Text is exact user-supplied copy or deliberately omitted.
[ ] No unsupported offer, price, date, statistic, claim, or capability appears.
[ ] Logo use relies on the supplied asset or is marked `logo pending`.
[ ] Model-specific limits are not asserted without a named provider.
[ ] The output says plainly whether it is a prompt package or generated video.

===============================================================================
11. ENGINEERING REQUIREMENTS
===============================================================================

Before implementation:
- Inspect the repository, agent conventions, and any existing generation,
  storage, authentication, and deployment capabilities.
- Reuse the current framework and existing brand source of truth.
- Identify unknown provider constraints; do not invent them.
- Propose a phased plan before broad architectural changes.

During implementation:
- Keep agents modular and independently testable.
- Validate structured outputs before handing them to the next stage.
- Use timeouts, bounded retries, and clear errors for any provider calls.
- Keep provider credentials in environment variables or secure secret storage.
- Never expose secrets or sensitive user data in prompts or logs.
- Place provider-specific behavior behind an adapter.
- Test prompt construction, timing arithmetic, routing, and QA decisions.
- Test provider behavior with mocked responses if an adapter is implemented.
- Document setup, configuration, agent roles, and provider extension points.

Do not:
- Rewrite unrelated parts of the application.
- Add a video provider or editor without explicit scope and credentials.
- Treat a generated video prompt as a generated video.
- Require a specific model's prompt syntax for the shared contract.
- Let agents silently alter the brief or approved campaign copy.
- Store secrets in source control or send assets without user consent.
